# `data/audit/`

Everything the pipelines write about what they did and measured: data-quality
reports, model evaluation reports, experiment results, figures, run logs and the
record of every look at the test split. The data itself is in `data/bronze`,
`data/silver`, `data/gold` and `data/tmp`.

Paths in this folder are named after a **run tag** (`h30_seed0`, `h30_q1q2_q3`,
...). A tag is what `--tag` / `TRAIN_TAG` / `MERGED_TAG` / `RUN_TAG` was given,
so two runs never overwrite each other; an untagged name is the historical
fixed one. The horizon is in the name too (`h30` = 30-day label).

## What git tracks here

`.gitignore` ignores the contents of every sub-folder (`data/audit/*/*`) and the
test-access log, and re-includes only what is listed below. A file marked
**tracked** is in git; **local** means it exists only on the machine that ran
it and can be regenerated by the command named.

| Tracked | Where |
|---|---|
| The six loose files directly in `data/audit/` | `agent_fleet_run.json`, `agent_pit_validation*`, `agent_point_in_time*`, `family_calibration.json` |
| Results of the Q1+Q2 -> Q3 2026 runs | `cascade_q3_h30/`, `cascade_q3_h44/`, `cascade_q3_h60/`, `horizon_q3/`, `deep_dive_q3_h30/`, `cluster_policy_h30/`, and the `*_q1q2_q3.json` files in `data_quality_reports/` |
| Placeholders | `.gitkeep` in `data_quality_reports/`, `dataset_versions/`, `feature_registry/` |
| This file | `README.md` |

Everything else is local. The per-run training plots are not tracked here
because the same files are tracked in `frozen_runs/<run id>/figures/`.

## Files directly in `data/audit/`

| File | What | Written by |
|---|---|---|
| `test_access_log.jsonl` | One line per computation on the test split: time, git commit, variant, purpose, extra settings (horizon, seed, nets). Append-only; it is how the number of looks behind a reported result is a fact, not a recollection. **Local, never committed.** | `src/models/access_log.py::record_test_access`, called by `make train`, the experiments, `evaluate-frozen`, `compare_horizons` |
| `agent_fleet_run.json` | A MAPE-K agent run over the fleet (decisions, tiers, outcomes). Uses a look-ahead backtest, so its precision is not quotable (runbook 4.7). **Tracked.** | `make agent-fleet` (`pipelines/run_agent_fleet.py`) |
| `agent_point_in_time.json`, `agent_point_in_time_observations.parquet` | The flagging policy measured the way it would run: fixed-date snapshots judged on what happens next. The JSON is the summary, the parquet the per-drive observations (53 MB). **Tracked.** | `make agent-pit` (`pipelines/run_point_in_time.py`) |
| `agent_pit_validation.json`, `agent_pit_validation_observations.parquet` | The same on validation-window snapshots, used to fit the per-family recalibration (40 MB). **Tracked.** | `make family-calibration` |
| `family_calibration.json` | Per-drive-family recalibration fitted on the validation snapshots and judged on the test ones (runbook 4.10). **Tracked.** | `scripts/evaluate_family_calibration.py` |

## Folders

### Data layers and registry

| Folder | What | Written by |
|---|---|---|
| `dataset_versions/` | One JSON per label build (`<UTC timestamp>.json`): the gold feature content hash, the gold labels' path and row count, and the feature-registry and model-config versions. It pins which data a model was trained on. | `make build-labels` (`src/labels/dataset_version.py`) |
| `feature_registry/` | `v<N>.json`: every gold feature column with its family, window and description. | `make build-features` (`src/features/registry.py`) |
| `model_cards/` | `v1_h<H>d[_<tag>].json` / `.md`: the model card of each `make train` run (data, features, metrics, limits). | `make train` |

### `data_quality_reports/`

Reports from the pipeline stages and the training runs.

| File | What |
|---|---|
| `backblaze_profile.json` | Profile of the ingested bronze data: row count, columns, null share per column, partition count. Written by `make ingest-backblaze`. |
| `silver_quality_report.json` | Pass/fail checks on silver (no null dates, no duplicate drive-day-attribute, positive capacity, failure date after date) with violation counts. Written by `make build-silver`. |
| `label_imbalance_report.json` | Positive, negative and censored row counts per horizon and split. Written by `make build-labels`. |
| `model_evaluation_report[_<tag>].json` | The full evaluation of a `make train` run: row- and drive-level metrics at the chosen threshold on validation and test, action-tier results, bootstrap intervals, calibration, top-K, two-stage report (candidates, Stage 1 flag rate, matched-recall gain), warning lead time. The source of the runbook's training tables. |
| `action_tiers[_<tag>].json` | The warn / cordon / migrate / drain thresholds a run tuned on validation, read by `score-fleet` and the agent. |
| `merged_evaluation_report_<tag>.json` | The merged-approach run (`make train-merged`): LightGBM, AFT, Cox, LSTM, TCN and the rank blends on the same drives. |
| `sequence_evaluation_report*.json` | LSTM / TCN runs (`make train-sequence`): per seed (`_s1`..`_s3`), per architecture (`_tcn_...`), and `.smoke` trial runs. |
| `sequence_tuning_t1..t3.json` | The validation-only tuning passes of the LSTM (`--train-only`). |
| `sequence_vs_tree.json`, `sequence_vs_tree_seeds.json` | The LSTM against LightGBM, and the blend, over seeds (`scripts/compare_sequence_vs_tree.py`). |

Files tagged `h30_q1q2_q3`, `h44_q1q2_q3` and `h60_q1q2_q3` belong to the
Q1+Q2 -> Q3 runs and are tracked; `h30_seed0` is the April-May window run.

| Doc section | Source here |
|---|---|
| Runbook 1.1.4 and `docs/q3_horizon_and_cascade_run.md` | `data_quality_reports/*_q1q2_q3.json`, `cascade_q3_h*/`, `horizon_q3/`; figures also in `docs/figures/q3_2026/` and `frozen_runs/<run id>/figures/` |

| Runbook 4.7 - 4.10 | `agent_point_in_time*`, `agent_pit_validation*`, `family_calibration.json` |

To regenerate the runbook tables from a result folder:

```bash
# the report argument is required by the script; --cascade reads the experiment JSON
make merged-tables REPORT=frozen_runs/fb58d9576c6146ba94c13389005fa15b/merged_evaluation_report.json \
    TABLES_ARGS="--cascade data/audit/cascade_q3_h30/experiment_two_stage.json"
```
